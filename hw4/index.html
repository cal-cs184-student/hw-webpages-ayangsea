Part 3: Handling collisions with other objects

For collisions with sphere, we first calculate whether or not the point mass' position is inside the sphere. If it is outside, then, we calculate the direction of the position vector to the center of the sphere. Then, we move in that direction from the origin by radius distance to get the tangent point. Next, we calculate the correction vector by calculating the tangent point minus the last position, then we update the point mass' position by last position plus the correction vector scaled by the friciton constant.

For collisions with the plane, we first calculate whether or not the point mass went from one side of the plane to the other. To do this, we calculate the dot products of both the position minus the plane's point with the normal and the last position minus the plane's point with the normal. If they have the same sign, we know that the point did not collide. Then, we project the vector pm.position - plane.point onto the plane's normal vector to get the point of intersection with the plane. We then calculate the correction vector the same way as for spheres and update it the same way.

Part 4: Handling self-collisions

To handle self-collisions efficiently, we implemented spatial hashing to avoid an O(n^2) comparison of every point mass against every other point mass.

In the function hash_position, we partition 3D space into boxes of dimensions w * h * t where w = 3 * width / num_width_points, h = 3 * height / num_height_points, and t = max(w, h). Each position is truncated to its box coordinate using fmod, then hashed to a unique float using the large prime number scheme (x * p + y) * p + z.

In the function build_spatial_map, we clear the existing map, then iterate over all point masses and insert each one into the vector corresponding to its hashed position. This groups nearby point masses into the same bucket.

In the function self_collide, for a given point mass we look up its hash bucket and check all candidate point masses within it. For each candidate that is within 2 * thickness distance (and is not the point mass itself), we compute a correction vector that would push the point mass to be exactly 2 * thickness away. Then, accumulate all correction vectors, average them, scale by simulation_steps, add the result to the point mass position

Varying values of ks and density

Varying ks changes the stiffness of the spring. With low ks values, the cloth is more loose and floppy. With high ks values, the cloth is more stiff and rigid and resists deformation Varying density changes how heavy the spring is. Low density values result in the cloth being lighter and the springs bounce up more. With high density values, the spring sags under gravity more and it is harder for it to hold up.
