Overview

In this homework, we implemented a real-time cloth simulation using a mass-and-spring system. We started by building the cloth's grid of point masses connected by structural, shearing, and bending springs (Part 1), then used Verlet integration with external forces and spring correction to simulate motion over time (Part 2). We implemented collision handling for spheres and planes (Part 3) and spatial hashing for efficient self-collision detection to prevent the cloth from clipping through itself (Part 4). Finally, we wrote GLSL shaders including Blinn-Phong lighting, texture mapping, bump and displacement mapping, and environment-mapped mirror reflections (Part 5). One of the most interesting things we learned was how much the simulation parameters of spring constant, density, and damping affect the cloth's behavior, and how small changes can make the cloth look like completely different materials.

Part 3: Handling collisions with other objects

For collisions with sphere, we first calculate whether or not the point mass' position is inside the sphere. If it is outside, then, we calculate the direction of the position vector to the center of the sphere. Then, we move in that direction from the origin by radius distance to get the tangent point. Next, we calculate the correction vector by calculating the tangent point minus the last position, then we update the point mass' position by last position plus the correction vector scaled by the friciton constant.

For collisions with the plane, we first calculate whether or not the point mass went from one side of the plane to the other. To do this, we calculate the dot products of both the position minus the plane's point with the normal and the last position minus the plane's point with the normal. If they have the same sign, we know that the point did not collide. Then, we project the vector pm.position - plane.point onto the plane's normal vector to get the point of intersection with the plane. We then calculate the correction vector the same way as for spheres and update it the same way.

Part 4: Handling self-collisions

To handle self-collisions efficiently, we implemented spatial hashing to avoid an O(n^2) comparison of every point mass against every other point mass.

In the function hash_position, we partition 3D space into boxes of dimensions w * h * t where w = 3 * width / num_width_points, h = 3 * height / num_height_points, and t = max(w, h). Each position is truncated to its box coordinate using fmod, then hashed to a unique float using the large prime number scheme (x * p + y) * p + z.

In the function build_spatial_map, we clear the existing map, then iterate over all point masses and insert each one into the vector corresponding to its hashed position. This groups nearby point masses into the same bucket.

In the function self_collide, for a given point mass we look up its hash bucket and check all candidate point masses within it. For each candidate that is within 2 * thickness distance (and is not the point mass itself), we compute a correction vector that would push the point mass to be exactly 2 * thickness away. Then, accumulate all correction vectors, average them, scale by simulation_steps, add the result to the point mass position

Varying values of ks and density

Varying ks changes the stiffness of the spring. With low ks values, the cloth is more loose and floppy. With high ks values, the cloth is more stiff and rigid and resists deformation Varying density changes how heavy the spring is. Low density values result in the cloth being lighter and the springs bounce up more. With high density values, the spring sags under gravity more and it is harder for it to hold up.

Part 5: Shaders

A shader program runs on the GPU and determines how each vertex and pixel appears on screen. The vertex shader processes each vertex of a mesh, transforming positions from 3D world space into screen space and passing along normals, texture coordinates, and positions. The fragment shader then runs on every pixel within a triangle, using the interpolated data from the vertex shader to compute the final color via lighting and material effects.

The Blinn-Phong model sums three lighting components. Ambient (ka = 0.1, Ia = 1.0) provides constant base illumination so surfaces are never fully black. Diffuse (kd = 0.6) models light scattering equally in all directions, scaled by light intensity over distance squared and the dot product of the normal n with light direction l. Specular (ks = 0.8, p = 32) creates sharp highlights using the half-vector h between the light and view directions, raising dot(n, h) to the power p.

Bump vs Displacement Mapping

Bump resolution simulates surface details by using surface texture without changing the actual geometry of the mesh, while displacement mapping changes the actual geometry. This is obvious in the render, as bump mapping is a lot more flat than displacement mapping. In displacement mapping, you can way more clearly see the depth of the texture than bump mapping.

Feature 1: Spatially Varying Wind System

We implemented a wind force system that applies spatially and temporally varying forces across the cloth surface. Unlike simple uniform wind, this system creates realistic turbulence patterns. The wind strength varies across the cloth using sinusoidal patterns based on position, and time-based oscillations simulate gusts and fluctuations. We also added real-time GUI controls for wind strength, direction (x, y, z), and enable/disable.

The core calculation modulates a base wind vector by position-dependent factors (using sin/cos over the cloth's x and z coordinates) and a time-dependent factor for turbulence. A vertical oscillation component is also added for natural flutter. Before implementing wind, only gravity and spring forces affected cloth movement. After, the cloth exhibits realistic flutter, waves, and billowing effects.

When I set the wind strength to a low value of 5, the cloth draped over the sphere with only a slight lateral push to the right. It still mostly hung down under gravity, with some gentle flutter from the turbulence variation. When I increased the wind strength to 100, the cloth was blown fully horizontally off of the sphere, and I was only able to take a screenshot while quickly pausing the simulation. The spatially varying turbulence was more visible at high strength, creating uneven ripples across the surface rather than a perfectly flat sheet.
